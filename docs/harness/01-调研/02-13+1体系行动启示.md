---

### 3. Access（权限治理）

**当前状态**：⚠️ 部分

| 落地物 | 作用 |
|---|---|
| 工具治理白名单 | 13+1 角色 × 工具白/黑名单 |
| 红线 8 条 | 所有角色通用禁止事项 |
| 角色-关键词映射 | orchestrator 调度权限 |

**缺口**：
- ⬜ 角色之间调用工具的边界未细化（如 frontend-dev-guide 是否能直接调 backend API）
- ⬜ MCP 工具治理白名单未单独梳理（建议按"读/写/破坏性/外发"分级）

---

### 4. Recovery（回滚）

**当前状态**：⚠️ 半自动

| 现有机制 | 作用 |
|---|---|
| `git tag` | 关键版本标记 |
| `git revert` | 优先回滚（保留历史） |
| `git reset --hard` | 紧急回滚 |

**缺口**：
- ⬜ Harness 配置变更未走 git tag（如 AGENTS.md 变更应打 `harness-v1.x` tag）
- ⬜ Agent 产出物失败时的快速回滚 SOP 未沉淀

---

### 5. Integration（系统对接）

**当前状态**：✅ 已落地

| 落地物 | 作用 |

| team-orchestrator | 跨角色编排 |
| MCP / Connector | 工具侧对接（如墨刀、Figma、腾讯文档等） |

**下一步**：
- ⬜ 跑一次端到端：用户需求 → orchestrator → 3 角色 → 交付物，验证链路
- ⬜ MCP 调用失败的降级方案（用本地工具兜底）

### 6. Governance（合规）

**当前状态**：✅ 已落地

### 7. Observability（观测）

**当前状态**：❌ 缺口

**OPC 阶段不做**（团队<5 人用不上 trace/log/metrics 完整方案）

**未来补齐路径**（团队到 5 人时）：

```
最小观测方案：
├── LLM 调用日志（用 LangSmith / Helicone）
├── Agent 执行 trace（用 LangGraph visualize）
├── 错误率告警（Slack / 飞书 webhook）
└── 周报自动化（每周 evals pass rate 趋势）
```

## 五、本周可执行清单（5 项）

按 ROI 排：

1. **跑一次真实项目验证 evals**（2 小时）
   - 选一个现有项目（如 SaaS 方案生成器 / 宠宝树）
   - 让 AI 改一个模块
   - 跑 regression-cases.json 看哪些 case 命中
   - 记录到 `05-实战/项目记录.md`

2. **加 `SECURITY.md` 到 02-规范/**（30 分钟）
   - 密钥管理规范
   - 数据脱敏规则
   - 模型选择合规

3. **MCP 工具分级清单**（1 小时）
   - 在 `06-工具链/` 加 `MCP-工具分级.md`
   - 按 L1~L5（只读/写入/破坏性/外发/远程执行）梳理

4. **AGENTS.md 加 Harness 变更 tag 约定**（15 分钟）
   - 02-规范/AGENTS.md 末尾加"Harness 版本管理"段
   - 约定：`harness-v1.x` tag 标记 Harness 配置变更

5. **跑通一次端到端（orchestrator 链路）**（1 小时）
   - 用户需求 → orchestrator → 2-3 角色 → 交付物
   - 验证：状态是否正确流转、决策是否可追溯、产出物是否可验收

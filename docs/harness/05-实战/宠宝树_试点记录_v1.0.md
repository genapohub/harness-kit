## 五、evals 自身迭代（v0.1 → v0.2）

跑真实项目看 case 假阳性/假阴性——这正是行动启示里预言的能力，第一天就兑现：

1. **假阳性①**：`.env.example` 被跟踪被误报 → example 文件属合法，排除
2. **假阳性②**：`password = os.getenv(...)` 读取模式误报为硬编码 → 正则收紧为赋值形式（不跨行）+ 行内 getenv 过滤
3. **噪音治理**：`test_*.py / deploy/ / migrate_* / scripts/` 的 print 输出是设计意图 → 豁免清单
4. **增量模式**：`--since HEAD~1` 只查新 commit——历史存量不改写（改写 git 历史代价 > 收益），新增由增量守护

## 六、发现与更正

- **更正存量认知**：项目 README 记「.env 含微信 AppSecret 明文，建议轮换」——实测 `.env` **从未被 git 跟踪、从未进历史**（`git log --all -- .env` 为空），.gitignore 已有 `.env` 条目。git 层安全，本地明文属标准做法，风险从「高」降级；若设备共享过再轮换
- **新增风险**：DEV_MODE 固定验证码 123456 可直接登录，生产误开即弱认证 → 记入 tracker 风险表（中），建议后续加生产环境 fail-fast
- **存量债务**：4 个手写 API 测试脚本（test_*.py，print 式输出）后续可迁移 pytest 断言风格
